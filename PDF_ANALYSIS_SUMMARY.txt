CALL ME MAYBE — PDF CONTENT ANALYSIS

1) Core Concept
The project teaches function calling with small LLMs.

Main idea:
- A user prompt in natural language should be converted into a structured function call.
- The system must return:
  - function name
  - typed arguments
- It should NOT return the final natural-language answer.

Example from the subject:
Prompt: "What is the sum of 40 and 2?"
Expected style:
{
  "name": "fn_add_numbers",
  "parameters": {"a": 40, "b": 2}
}

2) Key Technical Principle
The subject emphasizes constrained decoding.

What that means:
- Generate output token-by-token.
- At each step, only allow tokens that keep output valid for:
  1) JSON syntax
  2) expected schema (valid keys, valid function names, valid parameter types)
- Do not rely on prompting alone for JSON correctness.

Goal of this approach:
- 100% parseable JSON
- high reliability even with a small model (Qwen/Qwen3-0.6B)

3) What You Are Asked To Build
You must build a Python program that:
- reads function definitions JSON
- reads prompt tests JSON
- uses the provided llm_sdk to choose the correct function and extract arguments
- writes one output JSON array where each item contains exactly:
  - prompt (string)
  - name (string)
  - parameters (object)

4) Input/Output Requirements
Input files (default in data/input/):
- function_definitions.json
- function_calling_tests.json

Output file:
- data/output/function_calling_results.json

Important constraints:
- no extra keys
- correct argument names
- correct argument types
- valid JSON always
- robust error handling for missing/invalid files

5) Mandatory Engineering Rules (from subject)
- Python 3.10+
- flake8 + mypy compliance
- type hints and docstrings
- pydantic classes for validation
- graceful error handling (no unexpected crashes)
- include Makefile targets: install, run, debug, clean, lint (and optional lint-strict)
- use LLM-based function selection (no heuristic routing)
- do not use private llm_sdk members
- forbidden: dspy and similar tooling including pytorch/huggingface/transformers/outlines (as stated in the PDF rules)
- expected execution style uses uv run python -m src ...

6) Expected Quality Targets
- Near-perfect functional accuracy (subject indicates ~90%+ for selection + arguments)
- 100% valid JSON outputs
- reasonable runtime (subject target: all prompts under 5 minutes)

7) README Expectations
README.md should include:
- description
- instructions
- resources and AI usage disclosure
- algorithm explanation (constrained decoding)
- design decisions
- performance analysis
- challenges faced
- testing strategy
- usage examples
- written in English

8) Submission Expectations
Repository should include:
- src/
- pyproject.toml + uv.lock
- llm_sdk/
- data/input/
- README.md

Do NOT include generated output directory in final submission.

---
Bottom line:
This assignment is about building a reliable, schema-safe function-calling pipeline from natural language prompts using constrained decoding, not about getting a conversational answer from the model.
